# ADR 0004: Local transactional Career persistence

Status: implemented within the user's Phase-3 request. Phase 0 (`4e06cc6`), Phase 1 (`5b6116a`) and Phase 2 (`fc6d396`) are accepted baselines. This decision adds local storage; it does not authorize Phase 4.

## Decision

Use PostgreSQL, SQLAlchemy 2.x Core tables and Alembic for the current workspace-scoped Career aggregate. Keep accepted Pydantic domain contracts authoritative and immutable; do not introduce a parallel mutable ORM domain model. Pin SQLAlchemy 2.1.3, Alembic 1.20.0 and psycopg 3.3.6 in the project/lockfile and check both Python 3.13 and 3.14. Acceptance uses real PostgreSQL 18.6 from an immutable official container-image digest. Dependency versions were checked when introduced against the [SQLAlchemy release page](https://www.sqlalchemy.org/download.html), [Alembic package release](https://pypi.org/project/alembic/), [psycopg package release](https://pypi.org/project/psycopg/) and [PostgreSQL supported versions](https://www.postgresql.org/support/versioning/).

Store only nine concrete current record kinds, their ordered provenance links, retained Career observations and a minimal workspace deletion ledger. A small identity anchor supplies stable FK targets for concrete historical refs; it accepts no arbitrary object kinds. Preserve canonical versioned JSON text for lossless domain round trips and derive relational columns explicitly. Verify both canonical contracts and every projection on read. Composite scope/revision/hash FKs, closed/NULL-safe checks and guard triggers add database integrity without attempting to copy the whole domain validator into SQL.

Use the full canonical record SHA-256 for the persistence business-object catalog, including review/status; keep the accepted own-review digest boundary for draft/requirement reviews. Exact claim/evidence dependency refs retain accepted snapshot-digest meaning. No universal Phase-2 digest semantics are rewritten.

Save complete validated snapshots within one transaction. Serialize each workspace with an advisory transaction lock and row lock; require the expected aggregate generation. Changed records advance exactly one revision. Explicitly reconcile downstream refs/reviews after a source change; never silently repair provenance or promote user/AI assertions. State changes that require observations commit with events describing actual new state. Bootstrap permits validated historical import; later jobs/applications/reviews/transitions cannot use that exception or an old redelivery to avoid their matching observation.

Retain immutable observation metadata with stable historical identity references. Exact source-event redelivery is a no-op and conflicting reuse fails while the event is retained. Persist five event payloads. Fail closed on `fit_assessment_recorded` because Phase 2 supplies no Assessment record; defining semantic assessment belongs to its later accepted milestone. No hidden CareerLab answer or invented placeholder can supply that missing truth.

Freeze the initial migration's PostgreSQL DDL independently of current mapping metadata. Apply migrations explicitly; never call `create_all` at runtime. Test fresh/repeated upgrade and disposable down/up, and inspect constraints, all enabled guards and frozen function bodies because [Alembic autogeneration](https://alembic.sqlalchemy.org/en/latest/autogenerate.html) does not cover every database behavior. PostgreSQL [CHECK constraints](https://www.postgresql.org/docs/current/ddl-constraints.html) cannot establish arbitrary cross-row domain truth; scope/dependency FKs and domain reconstruction address those relationships. Complete-snapshot revision comparison and locks are explicit rather than relying on an ORM version counter whose [documented scope](https://docs.sqlalchemy.org/en/21/orm/versioning.html) excludes bulk operations.

## Privacy and trust boundary

Keep connections local, credentials/private runtime files outside Git, SQL echo off and parameters hidden. Configured workspace/actor IDs and supplied engines are trusted attribution/capabilities, not authentication. The runtime DML role should not own the schema or have DDL/TRUNCATE capability; tests exercise that role. Database/host administrators remain trusted and can bypass guards. This phase does not add an authentication/role-provisioning system or claim production deployment readiness.

Discard superseded full prose immediately; preserve the current accepted application history and closed retained events. Provide explicit 90-day recorded-event pruning with a PostgreSQL clock guard, without claiming a background scheduler exists. Whole-workspace deletion inserts an immutable workspace/time-only ledger record and explicitly purges all source/dependent/event content. Ordinary removal and delete/reinsert cannot bypass provenance guards. Individual-object deletion is deferred until its dependent/history policy is defined.

A later deletion record must be preserved separately from an earlier backup and applied before restored data is read or served. The in-database ledger alone cannot protect an old full restore that lacks the tombstone. Provide minimal export/apply primitives and test their restore precondition; do not add a backup subsystem or promise physical secure erasure. Admission of sensitive real data still requires the accepted private local storage, access, retention/deletion, protected backup/export and owner-verified disk-encryption checks.

## Alternatives and consequences

A mutable ORM model would duplicate accepted domain meaning. A JSON-only object store would lose useful relational scope/current-dependency constraints. A fully relational rewrite of every nested field would create a second wire/validation language and unnecessary migration surface. Canonical text plus deliberately limited projections costs redundant storage and reconstruction work, but makes exact round trips and independent projection checks straightforward for this bounded slice.

Complete aggregate replacement is simpler than patch repositories and a generic unit-of-work framework. It requires callers to reconcile dependencies explicitly and serializes writes per workspace; it is not a multi-user/high-volume design. No indefinite full revision archive is retained. The event history is an observation log rather than event sourcing, workflow execution or proof of external delivery.

Do not split public CareerLab fixtures into claimed held-out sets or use evaluator answers to populate runtime requirements. Preserve both accepted manifests and add `careerlab-persistence-env-v1.json` for changed dependency/configuration hashes. The compatibility bridge remains unchanged, with requirements empty and the negative transition rejected.

Revisit this ADR when an accepted milestone introduces Assessment, a new wire version, individual-object deletion, an actual retention/backup caller, authenticated API access, a measured need for granular updates/concurrency, or consequential external execution. [Phase-3 design](../phase-3/design.md) and [acceptance evidence](../phase-3/acceptance-review.md) document the implemented boundary and checks. No API, inference, connector, UI, workflow runtime or Phase-4 work is added here.
