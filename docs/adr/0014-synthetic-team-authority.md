# ADR 0014 — Team authority is a verified session plus current scoped membership

Date: 2026-10-07. Status: provisional synthetic implementation; canonical acceptance pending.

Phase 26 needs multiple principals and shared review without making a requested workspace ID authoritative. Use a deliberately small PostgreSQL directory: organizations with explicit policy/organization administrators, workspaces with bounded members/roles/connector references, pre-issued synthetic sessions, immutable shared workflow versions and append-oriented configuration audit. The trusted operator provisions initial authority. Models, jobs, connector output and Workflow IR cannot provision sessions or membership.

The application receives a masked synthetic session token and requested workspace, verifies the server-stored token digest/expiry/revocation, then resolves current membership and policy. Organization/workspace IDs and actor/role assertions alone grant nothing. Only explicitly synthetic token format is supported; this is an identity harness, not a production login implementation, SSO or a public service. The accepted unauthenticated synthetic Career HTTP API remains unchanged.

Viewer reads shared runs. Operator starts/runs its own shared workflow and may publish a validated version. Reviewer inspects/approves or denies the exact action. Workspace admin governs workspace membership/connector references and step activation. Organization policy changes additionally require a server-provisioned organization administrator. Every fake effect requires current organization permission, connector resource scope, principal-pinned activation and exact approval. An administrator may also execute/review; mandatory separation of duties is a later explicit organization policy, not a claim made here.

Add a nullable run initiator with additive workflow migration **3** and a relational identity check. Old runs retain an unassigned initiator and cannot enter the team boundary. New duplicate business events cannot change execution principal. Shared approvals bind the execution principal separately from the reviewer; activation audit records the actual administrator separately from the enabled principal. Dispatch rechecks operator session/membership, reviewer eligibility, policy version, connector scope and activation. Revoking a reviewer membership invalidates its authority; logging out a reviewer does not itself withdraw an existing approval, which has explicit revocation and expiry.

One principal may be enabled per existing workflow step activation record. Sharing is workspace-wide, with no per-document employee ACL or account administration UI. This proves a small collaboration boundary; it does not assert enterprise tenancy. PostgreSQL runtime permissions prevent DDL and audit/session authority edits, but that shared database role is not tenant-isolated against arbitrary SQL compromise. Stronger isolation, real identity/session lifecycle, administrative audit completeness and external connector accounts require Phase-27 design and canonical evidence.
